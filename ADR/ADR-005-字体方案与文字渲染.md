# ADR-005：字体方案与文字渲染

- **状态**：已接受（阶段 2）
- **日期**：2025-08-02
- **提出**：Lin（架构师）
- **关联**：Q2、问题 013、G3（100% 离线）

## 背景

印章文字为中文，渲染依赖系统字体（宋体/黑体/楷体/仿宋/隶书）。Q2 拍板：**使用系统字体回退栈 + 运行时可用性探测，不嵌入 CJK 字体**。问题 013 警示跨平台字体缺失会导致排版错乱。

## 决策

- `src/core/fonts.ts` 定义 5 套 Windows 自带字体栈（见 架构设计.md §3.2）：SimSun / SimHei / KaiTi / FangSong / LiSu，每套带完整回退（如 `'SimSun','STSong','NSimSun',serif`）。
- 提供 `isFontAvailable(stack: string): boolean`，用 `document.fonts.check()` + 离屏 Canvas 度量双校验，运行时探测字体是否真实可用（隶书在英文版 Windows 需可选功能，可能缺失）。
- **不嵌入任何 CJK 字体**（避免 10MB+ 体积膨胀与版权风险），仅 `@fontsource/montserrat` 本地打包拉丁字体供 UI 西文使用（G3 离线要求，禁 CDN）。
- 字体缺失时 UI 给**中性提示**（"该字体当前不可用，已切换至替代字体"），不报错阻断，且仍保证导出可用（回退到同族 serif/sans）。

## 理由

- 目标平台为 Windows，5 套字体均系统自带，覆盖公章/财务/合同/个人全部场景，无需嵌入。
- 嵌入 CJK 会让安装包从数 MB 涨到数十 MB，且部分字体有分发授权限制。
- 运行时探测比静态假设更稳：同一份代码在中文/英文 Windows 都能优雅降级。

## 备选方案

- **嵌入 CJK 字体（如思源宋体）**：体积大、有版权、违背 Q2 → 否决。
- **webfont CDN 加载**：违反 G3「100% 离线」→ 否决。
- **仅用单一字体不分选项**：丧失印章风格差异（F-30 要求多字体）→ 否决。

## 影响

- `fonts.ts` 是字体真相源；`FontCard.vue` 展示 5 选项 + 缺失提示。
- `buildSvg` 直接引用 `design.fontFamily`（已为完整栈字符串），无需额外映射。
- QA 验证需分别在中文版与英文版 Windows 跑一遍 `isFontAvailable` 路径。

## 遵循约束

G3（离线）；问题 013；Q2 拍板。
