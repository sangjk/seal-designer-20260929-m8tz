# ADR-004：名字与微软身份分离策略

- **状态**：已接受（阶段 2）
- **日期**：2025-08-02
- **提出**：Lin（架构师）
- **关联**：问题 001、问题 003、问题 007、问题 008

## 背景

软件涉及**三套互不相干的"名字"**，历史上极易混用导致上架失败或 exe 乱码（问题 001/003/007/008）：

1. **用户可见产品名**：应中文「印章生成器」，友好、符合品牌。
2. **微软包身份（Package Identity Name）**：主理人拍板固定为 `sangkl.30724BA61D061`，由商店/侧载体系锁定，**发布后不可改**。
3. **可执行文件名 / Cargo 包名**：必须 ASCII（如 `seal-designer`），否则 Windows 下 exe 名乱码、Release 资产名违规。

## 决策

三处**严格分离、各填各的**，互不派生：

| 位置 | 字段 | 值 | 说明 |
|---|---|---|---|
| `tauri.conf.json` | `productName` | `印章生成器` | 用户可见（安装界面/标题） |
| `tauri.conf.json` | `mainBinaryName` | `seal-designer` | EXE 文件名（ASCII，防乱码） |
| `src-tauri/Cargo.toml` | `name` | `seal-designer` | Rust 包名（ASCII） |
| `msix/AppxManifest.xml` | `Identity Name` | `sangkl.30724BA61D061` | 微软包身份（CI 注入，不手改） |
| GitHub 仓库名 | — | `seal-designer` | ASCII（约束 12） |

- CI 在打包 MSIX 时将 `AppxManifest.xml` 的 `Identity Name` 与 `Publisher`（`CN=3F86E209-...`）从模板注入，**不进 Rust 源码**。
- 本地 `tauri dev` / NSIS 构建只用到 `productName` + `mainBinaryName`，与微软身份无关，调试零冲突（问题 008）。

## 理由

- 微软身份一旦发布不可改，必须与"可随时改的产品名/文件名"解耦，避免后续改名污染身份。
- EXE 中文名在 Windows 资源管理器/任务管理器显示会乱码，ASCII 是唯一稳妥解。
- 仓库名 ASCII 满足约束 12，且 Release 资产名 `seal-designer_x.x.x_x64-setup.exe` 全 ASCII（问题 007）。

## 备选方案

- **全中文**：exe 乱码、商店身份无法填写中文 → 否决。
- **全 ASCII**：用户可见名 `seal-designer` 不友好、品牌不符 → 否决。
- **由 productName 派生 Identity**：改名即改身份，违反"身份锁定" → 否决。

## 影响

- 工程师改产品名只需动 `tauri.conf.json` 的 `productName`，绝不动 `AppxManifest` 的 `Identity`。
- CI 脚本（`pack-msix.ps1`）负责身份注入与一致性校验（与 `tauri.conf` 的 `productName` 可不同，但需显式记录）。

## 遵循约束

约束 12（仓库名 ASCII）；问题 001/003/007/008。
