# ADR-007：导出管线职责划分与软锁闸门

- **状态**：已接受（阶段 2）
- **日期**：2025-08-02
- **提出**：Lin（架构师）
- **关联**：D1、D3、问题 010、问题 011、问题 015、F-41

## 背景

导出 PNG/SVG 是软锁的付费边界（F-44~F-46），且预览与导出必须像素级一致（F-41）。两个核心矛盾：(1) 若 Rust 侧用 `resvg + image` 重渲染导出，做旧算法必与前端 Canvas 漂移（D1）；(2) 若前端直接写文件，软锁可被 JS 绕过（D3/问题 011）。问题 010 还警示 `fs` 插件开放会被滥用。

## 决策

- **渲染 100% 留在前端**：`buildSvg` 生成 SVG 字符串，`exportRaster` 用原生 Canvas 2D 渲染 3× 透明 PNG（`Uint8Array`）；SVG 导出直接拿字符串。Rust **不做任何印章渲染**。
- **落盘闸门只在 Rust**：仅 `export_png(app, path, data: Vec<u8>)` 与 `export_svg(app, path, svg: String)` 两个命令能写文件；二者首行：
  ```rust
  if !unlock::store::read(&app).export_unlocked { return Err(AppError::Locked); }
  ```
- **`fs` 插件写权限不授予**（`capabilities/default.json` 仅 `core:default` + `dialog:allow-save`）。前端唯一能"写"的是调起保存对话框，真正落盘由 Rust 接收 bytes 完成。
- 前端 `ExportBar` 的"未开通→弹支付"仅为 **UX 拦截**，非安全边界；安全边界是 Rust 闸门。

## 理由

- 单一渲染引擎（前端 Canvas）杜绝预览/导出视觉漂移（D1/问题 015）。
- 闸门下沉 Rust 后，前端无文件写能力，软锁无法被 JS 绕过（D3/问题 011），且无需服务器（约束 7）。
- 不开放 `fs` 写权限，从源头消除"前端绕道 `fs` 直写"的可能（问题 010）。

## 备选方案

- **Rust 用 resvg 重渲染导出**：实现双引擎、做旧必漂移、复杂度高 → 否决。
- **前端直写文件（授权 `fs`）**：软锁形同虚设 → 否决。
- **服务器校验解锁**：违反约束 7「无服务器激活码」→ 否决。

## 影响

- 职责红线生效：Rust 不渲染、前端不写文件、`core/` 不依赖 Vue/Tauri。
- `useExport` 编排：闸门检查（useUnlock）→ 渲染（前端）→ 保存对话框（dialog 插件）→ `invoke(export_*)`。
- `AppError::Locked` 统一错误，前端收到后弹支付（而非报错崩溃）。

## 遵循约束

D1/D3、约束 7、问题 010/011/015、F-41。
