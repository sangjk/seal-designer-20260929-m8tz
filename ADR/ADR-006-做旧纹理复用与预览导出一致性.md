# ADR-006：做旧纹理复用与预览导出一致性

- **状态**：已接受（阶段 2）
- **日期**：2025-08-02
- **提出**：Lin（架构师）
- **关联**：D4、问题 014、问题 015、项目坑 P1、P2

## 背景

做旧效果依赖一张 3.7MB 的噪声纹理 `sealNoisy.png`。网页版为规避 Canvas 跨源污染（tainted canvas 导致 `toBlob` 失败），把纹理内联成 **5MB base64**（项目坑 P1/P2）。桌面端必须换方案，且要保证**预览与导出的做旧视觉完全一致**（F-41 / AC-20，问题 015）。

## 决策

- 纹理 `sealNoisy.png` 放 `public/textures/`，随 `frontendDist` **同源内嵌**进 exe。
- WebView 通过 `useNoiseTexture` **懒加载**该同源 PNG 到离屏 Canvas（`drawImage` 不污染），预览与导出共用同一张纹理。
- 做旧合成逻辑 `src/core/aging.ts` 的 `applyAging(canvas, design, tex, scale)` 同时服务预览（scale=1）与导出（scale=3），保证像素同源。
- **纹理缺失兜底**：若同源加载失败，`aging.generateProceduralNoise()` 以三层程序化噪声（纤维 alpha 170–200 / 斑驳 60–160 / 麻点 30–90）还原质感，避免无纹理时直接崩。

## 理由

- 同源资源 `drawImage` 不会污染 Canvas，`toBlob('image/png')` 在导出时可用（解决问题 P2）。
- 不内联 5MB base64，安装包与内存占用大幅下降（解决问题 P1）。
- 预览与导出调同一 `applyAging` → 杜绝"预览好看、导出变样"的漂移（问题 015）。

## 备选方案

- **内联 base64（沿用网页版）**：体积大、内存高、仍可能因某些 Tauri 配置触发污染 → 否决。
- **WebGL 程序化噪声**：实现复杂、与 Canvas 2D 预览链路不一致 → 否决。
- **仅程序化无纹理**：质感不如真实扫描噪声自然 → 作为兜底而非主路径。

## 影响

- `public/textures/sealNoisy.png` 为必带资源（缺失时走程序化兜底，但视觉降级）。
- `src/core/aging.ts` 对 `core/` 纯函数化负责（不依赖 Vue/Tauri），保证双路径复用（D1）。
- 导出 PNG 3× 时纹理按 `scale` 同步放大采样，避免模糊/错位。
