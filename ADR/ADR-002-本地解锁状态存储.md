# ADR-002：本地解锁状态存储

- **状态**：已接受（阶段 2）
- **日期**：2025-08-02
- **提出**：Lin（架构师）
- **关联**：约束 7（无服务器激活码）、Q6、问题 018

## 背景

软件以 **9.9 元一次性本地解锁「导出 PNG/SVG」** 实现软锁（F-44~F-46）。约束 7 明确**禁止服务器激活码**体系，因此解锁态必须落本地。但纯前端 `localStorage` 易被清除或篡改，无法作为可信闸门（问题 018）。Q6 拍板：状态文件为 `app_data_dir` 下隐藏文件 `.unlocked.json`，含 `exportUnlocked: bool`。

## 决策

- 文件位置：Tauri `app_data_dir()` 下的 `.unlocked.json`（隐藏点文件，规避普通用户误操作）。
- 文件结构：
  ```json
  { "exportUnlocked": true, "orderRef": "SEAL...", "sig": "<HMAC-SHA256>" }
  ```
- 写入方：**仅 Rust**（`src-tauri/src/unlock/store.rs`），采用**原子写**（先写临时文件再 `rename`）。
- 防篡改：写入时以 `HMAC-SHA256(密钥=设备相关盐 + 文件内容)` 生成 `sig`；读取时校验，校验失败即视为 `export_unlocked=false`。
- 前端永远通过 `get_unlock_state` 读取 + 监听 `unlock:changed` 事件镜像，**不持有任何可写判断**。

## 理由

- 本地文件简单、可审计、离线可用，契合"无服务器"约束。
- HMAC 校验让文件具备防篡改能力，用户手动改 `true` 会因 `sig` 不匹配被拒绝。
- 原子写避免支付成功瞬间进程崩溃导致状态文件半截写入。

## 备选方案

- **Windows 注册表**：Windows 专用，破坏"桌面应用"可移植性，且仍需防篡改 → 否决。
- **加密 SQLite**：过重，单布尔值不值 → 否决。
- **前端 localStorage**：可被清/改，丧失闸门可信度（问题 018）→ 否决。
- **纯明文文件无签名**：易被改 → 否决（采用签名版）。

## 影响

- `unlock/store.rs` 是解锁态唯一真相源；`export_png`/`export_svg` 闸门直接读它（见 ADR-007）。
- 密钥盐取自设备稳定标识（如 `app_data_dir` 路径哈希），不入库、不随包分发。
- 调试期由 `#[cfg(debug_assertions)] dev_set_export_unlocked` 提供本地开关，release 不编译。

## 遵循约束

约束 7（无服务器）、安全问题 018（防篡改）。
